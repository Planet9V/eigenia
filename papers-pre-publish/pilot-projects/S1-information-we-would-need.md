# Information We Would Need

**Supporting document, Cyber Digital Twin Pilot**

---

Nothing on this list has to be created for the pilot. It is all material your
engineering teams already maintain. We have grouped it by what it lets us do, so it
is clear why each item matters and what is affected if a particular item is not
available.

## Documentation

| What | Why we need it |
|---|---|
| Engineering design and product specification documents | Establishes the structure of the asset and the relationships between its parts |
| Interface control documents | Tells the model how subsystems connect, rather than leaving it to be inferred |
| System design documents, high and low level | Fills in the detail behind the structure |
| Bills of materials | The basis for every compliance and vulnerability answer. This is the most important single input |
| Concepts of operation | Describes how the asset is actually used, which affects what matters |
| Hazard logs and safety analyses | Lets security requirements be derived from consequence rather than assigned by category |
| Reliability analyses | Supports the consequence side of the model |
| Configuration baselines, as designed and as built | Required to measure configuration accuracy |
| Minimum operating requirements | Defines what has to keep working, which sets priority |

Where any document is considered too sensitive to share in full, there are
straightforward alternatives that preserve the result: supplying structure without
performance values, having your own engineers run the ingestion so that only the
resulting model elements move, or running the session with your engineer at the
keyboard. Most of this list works perfectly well with the first option.

## People and access

| What | When |
|---|---|
| A named engineering contact for each asset | Before kickoff |
| Workshop time with engineering, operations, security, compliance and procurement | Start, middle and end, around three hours each |
| A secure dedicated cloud instance with GPU access | Before kickoff |
| Current timings for the agreed set of compliance questions | Captured live in the first workshop |
| Internal cost rates for engineering change | Mid-engagement, for the cost measure |

## Three things that matter most

If everything else has to be sequenced, these three determine whether the first
month is productive:

1. The equipment and component lists for the assets in scope.
2. Which design decisions remain open, and when each one closes.
3. A named contact on your side for documentation access.
