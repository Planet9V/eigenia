E.1  THE UNCONVERGED PUBLISHED RUN, REPRODUCED FIRST.

     COMMAND (the pre-14-September procedure, 60 restarts of 1,500 steps,
     three seeds, exactly as s6_timbre_capacity.py had it):

       python3 - <<'EOF'
       import numpy as np
       _R=np.array([(0.5,0.5,-0.5,-0.5),(0.5,-0.5,0.5,-0.5),(0.5,-0.5,-0.5,0.5)])
       def mp(P):
           T=P@_R.T; d=np.linalg.norm(T[:,None,:]-T[None,:,:],axis=2)
           np.fill_diagonal(d,np.inf); return d.min()
       def opt(n,restarts,steps,seed):
           rng=np.random.default_rng(seed+n); bv=-1.0
           for _ in range(restarts):
               P=rng.random((n,4)); cur=mp(P); step=0.35
               for s in range(steps):
                   i=rng.integers(n); k=rng.integers(4); old=P[i,k]
                   P[i,k]=min(1.0,max(0.0,old+rng.normal(0,step)))
                   v=mp(P)
                   if v>cur: cur=v
                   else: P[i,k]=old
                   if s%300==299: step*=0.6
               bv=max(bv,cur)
           return float(bv)
       for seed in (20260913,11111,99991):
           r={n:round(opt(n,60,1500,seed),4) for n in range(2,9)}
           print(seed,r,'violations at N=',[n for n in range(2,8) if r[n]<r[n+1]-1e-12])
       EOF

E.6  WHAT WAS CHANGED IN s6_timbre_capacity.py, AND WHY THE SEARCH CHANGED.

     (1) MONOTONICITY IS ASSERTED. assert_monotone() checks f(N) >= f(N+1) on
         both tables and raises with the offending pair rather than printing.
         This is the assertion that caught the unconverged run, and it now runs
         on every publication of this script.
     (2) THE EXHAUSTIVE CORNER SEARCH IS IN THE SCRIPT, for every N, printed
         beside the continuous table. It needs no seed and no scipy.
     (3) A SECOND ASSERTION: the continuous table must dominate the corner
         table at every N, since the corners lie in the cube.
     (4) --reseed REPEATS THE WHOLE TABLE AT THREE SEEDS and asserts every cell
         agrees to 1e-6, failing with the offending cell if not.
     (5) THE RESTART COUNT IS 600 polished starts per N (MPN_STARTS overrides).
         At 200 starts every cell agrees across the three seeds except N = 13;
         at 600 every cell agrees. That is the count at which re-seeding
         changes nothing, which is the convergence test the job asked for.

     WHY THE SEARCH ITSELF WAS REPLACED, SAID PLAINLY. The job asked for the
     restart count to be raised until three seeds agree. RAISING THE RESTART
     COUNT ALONE DOES NOT GET THERE: the old coordinate-jitter search at 1,200
     restarts of 4,000 steps still returns 1.0329 at N = 7 and costs 95 seconds
     for that one cell. What converges is polishing each start. The polish is
     legitimate and is not a change of problem:
       - section 2 of the same script already proves h is an orthogonal
         projection followed by an isometry, so the min pairwise timbre
         distance depends on the profiles only through their timbre images;
       - the reachable set T = h(cube) is exactly the rhombic dodecahedron
         {x : |x_i +- x_j| <= 1}, so the problem is a 3-D packing problem;
       - each start is polished by SLSQP on the epigraph form, maximise t
         subject to ||x_a - x_b||^2 >= t and x in T;
       - the DISC profile is recovered by walking the fibre, which section 2(b)
         proves is a straight segment in the direction (1,1,1,1)/2. The
         recovery is ASSERTED in the script, not assumed: the profile must lie
         in [0,1]^4 and must map back to the timbre point to 1e-9.
     DEPENDENCY, STATED AS THE RULES REQUIRE. The polish needs scipy; the rest
     of the script needs numpy; the corner search needs neither. If scipy is
     absent the script says so loudly, falls back to the old coordinate search,
     and labels its table as unconverged lower bounds. No behaviour is silent.
     Every seed is fixed. There is no unseeded randomness in any script here.
